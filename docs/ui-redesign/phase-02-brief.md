# TrayPilot 界面重设计 · 第二部分（已确认）

第一部分的整体视觉、三栏布局与真实程序图标已确认。本部分沿用雾白 / 石墨主题，设计隐藏规则管理与创建、编辑、删除流程。

## 页面与关键需求

- 主页面：顶部展示自动隐藏状态和全局暂停入口；下方为规则计数、搜索、范围筛选与列表；右侧显示选中规则的路径、匹配范围和当前图标状态。
- 范围筛选：全部规则 / 整个程序 / 单个图标。标签“所有图标”指同一程序路径的普通托盘图标，不包含音量、网络等系统控件。
- 状态：已自动隐藏、本次暂时显示、等待程序运行、全局暂停。用文字与图形同时表达，不只依赖颜色。
- 创建规则：一个弹窗完成“选择当前识别到的图标 → 选择范围 → 预览 → 保存”。默认“仅此图标”，精确控制；可改为“此程序的所有图标”。
- 多图标程序：正式界面的选择项须包含真实托盘图标、提示文本与必要的图标标识，不能仅按程序名称合并。示例每个程序只有一枚图标。
- 编辑规则：保留目标程序，仅更改匹配范围。实际单图标匹配需从当前扫描结果选择目标，程序未运行时不允许新建单图标规则；现有单图标规则仍可保留。
- 重复与覆盖：同路径的整个程序规则与其单图标规则不能意外重叠；原型将同一示例目标的重复提交拦截在弹窗内，保留选择并显示明确错误。正式版本允许同程序多个不同目标的单图标规则。
- 保存：自动隐藏运行时立即应用新规则；暂停时保存规则但等待继续执行。失败时保留表单，不显示成功提示。
- 暂停自动隐藏：全局暂停，保留规则，不恢复已经隐藏的图标。继续执行时保留本次运行的手动显示例外。
- 立即应用：继续自动隐藏并清除所有本次暂时显示的例外，重新隐藏匹配图标。按钮附近可见规则行为说明，执行后反馈。
- 删除：确认弹窗说明默认只移除规则；“同时恢复该规则匹配的已隐藏图标”默认不勾选。删除后提供撤销入口。
- 等待程序运行：规则不会失效，也不以错误状态呈现；程序图标再次出现后自动应用。
- 详情中提供“本次暂时显示”，明确原规则保留；高级匹配依据渐进展开，不让内部标识挤占主要流程。

## 与现有程序的关系

已核对 `Controller.cs` 的 `HiddenPaths`、`HiddenIcons`、`RulesPaused` 和手动显示例外机制：程序规则按规范化路径匹配，单图标规则按路径加 GUID，或路径加图标 ID 和窗口类匹配。

现有项目支持添加、删除、全局暂停状态、手动显示与重新应用；本次新增的是这些能力的可视化流程。独立暂停入口、范围编辑、删除时可选恢复、撤销等交互在原型中演示，正式落地需补充组合调用和失败回滚。尚未修改原生程序或真实设置。示例规则数和状态不代表当前电脑。

## 视觉与可访问性

沿用第一部分色彩、字重、间距、真实程序图标和 1.7 px 描边的控制图标。状态面板采用高不透明度表面；模态背景加遮罩与轻度模糊，让用户识别当前操作层级。

创建 / 编辑 / 删除使用原生 HTML dialog 演示：限制焦点在弹窗内，支持 Escape 取消并回到触发控件；表单有可见标签、范围单选、预览及内联错误。首屏不暴露未经扫描的 GUID / ID，正式程序在需要时显示实际匹配信息。

参考 ui-ux-pro-max：沿用已确认设计系统，针对模态焦点和内联验证分别检索 UX 指南；不重新生成不同视觉方向。
